# 每日热点 · 微信小程序

实时热搜 + AI 方法论视点。频道：生活、社会、科技、军事、娱乐、文化、音乐、汽车、财经。

解读统一采用**毛泽东思想、历史唯物主义、辩证唯物主义**的立场、观点、方法，坚持实事求是——**只基于公开事实摘要作方法分析，不猜测、不传谣、不对未证实信息下结论**。事实不足的热点会自动拒答，明确显示「事实不足 · 暂不解读」。

## 产品形态

- **首页「今日热点」**：默认「热搜」标签，展示**微博热搜 + 百度热搜**合并后的实时榜单（排名、热度、来源、事实摘要）；「推荐」按订阅频道混排；9 个频道标签按关键词自动归类
- **今日聚焦**（`pages/focus/focus`）：当日全站 Top 3 + 每个订阅频道各一条，统一入口查看 AI 视点
- **详情页**：事实与观点分离
  - 「事件概览 · 公开事实摘要」只展示热搜源提供的公开摘要，并给出原始链接
  - 「AI 视点」先用一句大白话给结论，再按矛盾分析法 / 历史唯物主义 / 实践论等逐条分析
  - 每条视点都标注 **AI 辅助生成**，并附「不猜测动机、不传播未经证实信息、事实以原文为准」声明
- **热点搜索**：在当日实时热搜榜单内检索标题与事实摘要；未开通云开发时检索本地示例
- **我的订阅**：勾选频道定制推荐流；可授权每日推送提醒（订阅消息）
- **降级**：未开通云开发、热搜源临时不可用、AI key 未配置时，界面会**明确标注**「示例」或错误原因，不会把写死内容伪装成实时内容

## 实时性是怎么实现的

```
微信小程序
   │  wx.cloud.callFunction
   ▼
fetchNews 云函数 ──► 微博热搜公开接口 ──┐
   │               百度热搜公开接口 ──┴─► 合并去重 / 分类 / 8 分钟缓存 / 当日归档
   │
   ├──► interpret 云函数 ──► DeepSeek API ──► AI 视点（按标题缓存 3 天）
   │        ▲
   │        └── prewarm 云函数（定时，每 10 分钟）预热 Top 20
   │
   └──► dailyPush 云函数（定时 08:00）推送当日最热一条
```

关键设计：

1. **事实与解读分离**：微博只有标题/热度，百度热搜带 `desc` 事实摘要。合并时同一话题优先保留百度摘要，作为 AI 解读的**唯一事实依据**。
2. **事实不足就拒答**：只有标题、摘要不足 24 字、或标题含「网传/疑似/爆料」且没有权威核实时，`interpret` 不调用大模型，直接返回「暂不解读」并缓存，既守原则也省钱。
3. **按需 + 预热**：详情页打开时生成（首次 5~15 秒），`prewarm` 每 10 分钟为 Top 20 中未生成的条目预热；已预热的条目打开即显示。
4. **跨用户共享缓存**：`interpret_cache` 按标题 MD5 缓存 3 天，同一热点只花一次钱。
5. **防滥用**：`interpret` 只接受热搜归档中存在的 id，并按 openid 限制每日生成次数（默认 80 次）。
6. **深链可回查**：每日热搜归档到 `news_cache` 的 `hot_YYYYMMDD` 文档，保留 7 天，分享链接在 7 天内可回查。

## 开通云开发（必须，实时功能依赖云函数）

小程序前端受「合法域名」限制，且 API key 不能放前端，所以实时抓取和 AI 调用都必须走云函数。以下步骤按顺序做一次即可。

### 1. 开通云环境

微信开发者工具 →「云开发」→ 开通（个人免费基础版足够）→ 记下**环境 ID**，填入 `js/config.js` 的 `CLOUD_ENV`（只有一个环境时可留空）。

### 2. 建数据库集合

云开发控制台 → 数据库 → 新建以下集合（权限选「仅创建者可读写」即可，云函数以管理员身份访问）：

| 集合 | 用途 |
| --- | --- |
| `news_cache` | 热搜缓存 + 每日归档 |
| `interpret_cache` | AI 视点缓存（按标题） |
| `ai_usage` | 每用户每日 AI 用量 |
| `subscribe_users` | 订阅消息额度与频道 |

> 云函数首次写入时会尝试自动创建集合；若你的环境不允许，请手动建好。

### 3. 申请 DeepSeek key 并配置

1. 到 <https://platform.deepseek.com> 注册，创建 API Key
2. 云开发控制台 → 云函数 → `interpret` → 配置 → **环境变量**：
   - `DEEPSEEK_API_KEY = sk-...`（必填）
   - `LLM_MODEL = deepseek-chat`（选填，默认）
   - `LLM_BASE_URL = https://api.deepseek.com`（选填，兼容其他 OpenAI 格式服务）
   - `AI_DAILY_LIMIT = 80`（选填，单用户每日生成上限）
   - `LLM_JSON_MODE = 1`（选填，默认开启；若换用的兼容服务不支持 JSON mode，设为 `0`）
   - `LLM_TIMEOUT_MS = 40000`（选填，单次大模型请求超时）
3. 在云函数配置里把 `interpret` 的**超时时间调到 60 秒**（默认 3 秒会导致大模型调用被中断）

> 任何 key 都不要写进 `js/config.js` 或前端代码，前端会被反编译。

### 4. 上传部署云函数

在开发者工具左侧目录，右键以下目录 →「上传并部署：云端安装依赖」：

- `cloudfunctions/fetchNews`
- `cloudfunctions/interpret`
- `cloudfunctions/prewarm`
- `cloudfunctions/subscribe`
- `cloudfunctions/dailyPush`

部署后确认（**超时时间必须调**，默认 3 秒会把外部请求掐断）：

- `fetchNews` 超时调到 **20 秒**（要并行请求微博、百度两个外部接口）
- `interpret` 超时调到 **60 秒**（大模型生成需要 5~20 秒）
- `prewarm` 超时调到 **60 秒**，定时触发器 `prewarmHot`（每 10 分钟）已生效
- `dailyPush` 超时调到 **60 秒**，定时触发器 `dailyHotPush`（每天 08:00）已生效
- `prewarm` 内部调用 `interpret` 的 SDK 超时已设为 45 秒（`cloud.init({ timeout })`）；若你调大 `interpret` 的超时或 `LLM_TIMEOUT_MS`，请同步调大 `prewarm` 的 SDK 超时
- 手动测试 `fetchNews`（参数 `{}`）能返回 `ok: true` 和热搜列表
- 手动测试 `interpret`（参数 `{"id":"<某条热搜 id>"}`）能返回 `ok: true`

### 5. 配置每日推送（可选）

1. 小程序后台 →「订阅消息」→ 从公共模板库选一个「每日热点提醒」类模板，记下**模板 ID** 与字段名
2. 模板 ID 填入 `js/config.js` 的 `SUB_TEMPLATE_ID`，同时配置到 `dailyPush` 云函数环境变量 `SUB_TEMPLATE_ID`
3. 若模板字段不是 `thing1/time2`，修改 `cloudfunctions/dailyPush/index.js` 的 `buildData`
4. 个人主体只能「一次性订阅」：用户每授权一次只能推一条，所以「我的订阅」页有「续订」按钮
5. 测试时 `miniprogram_state` 默认 `trial`（体验版）；正式发布把 `dailyPush` 环境变量 `PUSH_ENV` 设为 `release`

## 费用与配额

- 热搜抓取本身**不产生 API 费用**（微博/百度公开接口）；服务端对 `force` 刷新做了 60 秒最短回源间隔，避免高频调用
- AI 解读按 DeepSeek 官网按量计费。每天约 20 条预热 + 用户按需生成，通常每天几分钱到几毛钱量级，以官网价格为准
- 同一条热点只生成一次（3 天缓存），热点榜单快速轮换时费用会略高
- `interpret` 默认单用户每天最多生成 80 次，可在环境变量 `AI_DAILY_LIMIT` 调整
- `prewarm` 每轮最多生成 4 条（并发 4），超时/失败不会重试同一条，下一轮自动继续

## 调整内容与提示词

- **换数据源 / 调频道归类**：`cloudfunctions/fetchNews/index.js` 的 `fetchBaidu`、`fetchWeibo`、`CHANNEL_RULES`
- **调解读风格 / 方法论要求**：`cloudfunctions/interpret/index.js` 的 `buildMessages` 系统提示词
- **调事实边界**：同文件的 `precheck`（哪些情况直接拒答）和 `cleanResult`（输出校验）
- **调预热数量**：`cloudfunctions/prewarm/index.js` 的 `TOP_N` / `BATCH`
- **调缓存时长**：`fetchNews` 的 `TTL`（默认 8 分钟）、`interpret` 的 `CACHE_TTL`（默认 3 天）

修改 `fetchNews` 的文章结构时，请同步检查 `js/source.js` 的 `normArticle` 与详情页字段。

## 上线合规提醒（务必阅读）

- **AI 生成内容标识**：界面已标注「AI 辅助生成」「AI 生成内容 · 仅供方法论参考」。正式上线还需遵守《生成式人工智能服务管理暂行办法》《互联网信息服务深度合成管理规定》，在显著位置持续标识 AI 生成属性
- **新闻资质**：小程序后台选择类目时，「资讯/时政新闻」需要《互联网新闻信息服务许可证》，个人主体无法提供。可行定位是「**工具-信息查询**」或「教育/文化」，内容以**已公开信息的评论解读、知识普及**为主，不做新闻采编与首发报道
- **数据源授权**：微博/百度热搜是公开页面接口，非正式开放平台 API，可能变更或限制访问。当前实现用于学习/演示；**商业上线前应取得内容授权，或改用有展示授权的资讯 API**
- **事实与观点分离**：详情页已把「公开事实摘要」与「AI 视点」严格分开；AI 只基于热搜源提供的事实摘要分析，不补写事实
- **敏感题材**：`interpret` 的提示词要求对个人私生活、未成年人、未定论刑事案件、民族宗教、军事外交敏感细节不作评价；事实不足直接拒答
- **名称与备案**：名称避免含「新闻」「日报」等需资质字样；2023 年 9 月起新小程序上架前需完成 ICP 备案

## 运行

1. 微信开发者工具（稳定版）→ 导入本项目目录
2. 本项目为**小程序**类型，AppID 用你自己的小程序账号；游客模式亦可运行
3. 未开通云开发时，模拟器展示本地示例内容，界面会标注「示例」；开通并配置 key 后自动切换为实时热搜 + AI 视点
4. 点「预览」扫码上真机
